# 关键用户旅程与验收

这些旅程连接分散需求。E2E 可以自动化步骤，但注明人工的观察不能由 Codex 自评替代。

## J-001 新建并保存中文文档

1. 启动到未命名混合编辑文档。
2. 使用微软拼音输入标题、列表、粗体、链接和中文标点。
3. 源码模式检查原始 Markdown，再切回；光标/撤销保持。
4. Ctrl+S 选择路径，保存为 UTF-8 CRLF。
5. 关闭重开，内容和显示一致。

验收：DOC-001..005、EDT-001..008、DATA/EDIT；人工确认 IME 手感。

## J-002 编辑现有仓库文件而不制造噪声

1. 打开含 LF、引用定义、手排表格、HTML 和无尾换行的 README。
2. 只修改一个段落中的一个词。
3. 保存并查看字节 diff。

验收：只有对应字节变化；EOL、表格、HTML、引用和尾部状态不变。任何全文件格式化为 P0。

## J-003 文件夹写作

1. 打开 10,000 文件工作区。
2. 快速打开中文路径文件，在文件树定位。
3. 从大纲跳转，执行全局搜索并取消一次大搜索。
4. 新建、重命名、移动文件，删除到回收站。

验收：输入线程不中断，路径授权不越界，结果和树及时更新，危险操作确认。

## J-004 外部冲突

1. 打开文件并在应用中产生未保存修改。
2. 外部编辑器修改同一磁盘文件。
3. 自动保存触发。

验收：自动保存暂停；用户可比较/重载/本地另存/确认覆盖；任何选择前两份内容均可恢复。

## J-005 崩溃恢复

1. 新建未命名文档和一个已命名脏文档。
2. 输入复杂中文、表格和公式后强制结束进程。
3. 重启并逐个恢复，保存到新路径。

验收：最新有效 revision 恢复；坏最后快照回退；无虚假成功；正常保存清理正确记录。

## J-006 图片资产流程

1. 在已保存文档中粘贴截图并选择复制到 `./assets`。
2. 重命名、移动并重新加载图片。
3. 尝试删除并取消，再删除到回收站。
4. 模拟 Markdown patch 失败。

验收：路径最小更新、资源事务回滚、取消无副作用、磁盘与源码不分裂。

## J-007 学术文档

1. 打开含 YAML、脚注、引用、公式编号、表格、TOC 和 Mermaid 的长文。
2. 编辑表格行列、公式和图表源码。
3. 导出 PDF、HTML 和 DOCX。

验收：混合/源码无漂移，坏公式/图表回退源码；PDF/HTML 离线完整，Pandoc 缺失时只影响 DOCX。

## J-008 智能复制粘贴

1. 从浏览器、Word 和 Google Docs 风格 fixture 粘贴标题、列表、链接和表格。
2. 分别用智能粘贴和纯文本粘贴。
3. 从应用复制为富文本、Markdown、HTML、纯文本到外部应用。

验收：语义符合所选模式，脚本/危险属性被移除，操作单次可撤销。

## J-009 主题和显示

1. 依次切换六套独立实现的内置主题，并按 `REF-021` 与对应 `COMP-*` 对照其公开可观察效果。
2. 切换系统跟随并加载自定义 CSS 主题，确认自定义主题与内置主题隔离。
3. 在 100/150/200/250% 缩放、高对比和窄窗口下操作菜单、侧栏、编辑器、设置和弹层。

验收：六套主题的布局、字体层级、颜色、控件状态和 Markdown 元素效果逐项达到证据定义；编辑可读、控件不截断、焦点可见、安全对话框不被主题隐藏，远程 CSS 资源受控。证据不足或已知差异不能签署通过。

## J-010 导出失败恢复

1. 对含本地/缺失图片、公式和图表的文档导出 PDF。
2. 目标目录变只读，随后取消另一次导出。
3. 修正目标后使用“上次导出”。

验收：源文档不变；失败无半成品或明确标识；取消终止渲染；上次设置不会误覆盖其他格式目标。

## J-011 命令行和文件关联

1. 从资源管理器双击 `.md`。
2. 从 PowerShell 用含空格/中文路径启动一个文件和文件夹。
3. 第二次启动应用传入新文件。

验收：参数不经 shell 拼接；单实例按设置路由；不存在路径安全处理；当前脏文档不丢失。

## J-012 安装、升级和卸载

1. 干净 VM 安装，创建设置、主题、恢复记录和用户 Markdown。
2. 覆盖升级到 RC。
3. 卸载并选择保留数据，再重装。
4. 再次卸载选择清理应用数据。

验收：用户 Markdown/工作区永不删除；保留选择有效；清理范围仅 userData；升级失败能回滚应用。

## J-013 Pandoc 导入

1. 在已配置 Pandoc 的环境中导入包含标题、列表、表格、脚注和图片的 DOCX，以及 RST/EPUB/LaTeX 各一个自建样本。
2. 查看转换警告，在未命名会话中编辑导入结果。
3. 首次另存为 Markdown，确认 staging 图片提交到目标旁的受控资源目录。
4. 分别测试取消、Pandoc 缺失、非法输出资源路径和转换失败。

验收：源文件哈希始终不变；成功结果为可编辑的未命名 Markdown 会话；资源路径不逃逸；失败或取消不创建部分会话；无 Pandoc 不影响 Markdown 打开及 HTML/PDF/图片导出。
