# 产品章程

## 1. 产品定义

项目暂用代号 **Lattice**。它是一个本地优先、单栏混合编辑的 Windows Markdown 桌面应用。最终目标是使用独立品牌和独立实现，完整复刻 Typora 1.13.8 在 Windows 10/11 上公开可确认的用户可观察产品表现。

“完整复刻”具体指：

- 在单个编辑区中重现即时排版与源码标记按需显隐的编辑模型；
- 重现可公开确认的窗口结构、菜单、工具栏、侧边栏、状态栏、设置分类、快捷键和状态反馈；
- 重现 Markdown、文件、图片、剪贴板、主题、导入导出和 Windows 系统工作流；
- 使用项目自己的 CSS、字体策略和资源，重现六套内置主题的视觉效果；
- 同一 Markdown 文件无损打开、编辑和保存，数据安全不得因视觉复刻而降低；
- 每项结论都通过公开证据、需求、设计、测试和报告形成可追溯闭环。

“兼容”只是复刻完成后的结果属性。只支持相同文件格式、主要功能或相似流程，不足以认定复刻完成。

## 2. 成功标准

1. 所有 `COMP-*` 复刻验收项达到 `passed`，已知产品差异为零。
2. 未编辑文件保存后字节完全相同；编辑文件仅产生与用户操作对应的最小源码变更。
3. 中文 IME、撤销重做、跨块选择、外部文件变更和崩溃恢复连续四周日用无数据丢失。
4. Windows 10/11 x64 安装、卸载、文件关联、命令行打开和导出流程通过发布门禁。
5. 没有严重或高危安全问题，没有从不可信 Markdown/HTML 到 Node 或系统命令的未授权路径。
6. 每个复刻项都有适用 `REF-*`、迭代需求、自动化或人工测试以及出口证据；关键 high/medium 证据缺口为零。

## 3. 用户与核心场景

- 普通写作者：快速编写 README、博客、笔记和长文。
- 开发者：编辑含代码块、相对链接、HTML 和项目图片的仓库文档。
- 学术用户：使用公式、脚注、引用、表格和 Pandoc 导出。
- 中文用户：依赖稳定的拼音/五笔输入法、全角标点和中英文混排。

主要旅程：打开文件或文件夹 → 在混合模式写作 → 用大纲和搜索导航 → 管理图片与链接 → 保存 Markdown → 导出或交给其他工具继续处理。

## 4. 范围

### 包含

- Windows 桌面应用、单文档窗口、文件夹工作区。
- Markdown 源码模式和单栏混合模式。
- 版本化公开证据能够确认的 Typora 1.13.8 Windows Markdown、文件、工作区、图片、六套主题、设置、导出及可选 Pandoc 导入能力。
- 本地偏好、恢复、最近文件、文件关联和命令行入口。
- 简体中文和英文首发；其他官方语言在兼容收尾阶段扩展。

### 首发不包含

- 账号、云同步、实时协作、在线笔记库、AI 写作、插件市场。
- 手机和平板端。
- 浏览器版。
- Typora 激活、付费、遥测或许可体系的仿制。
- 未在 Typora 1.13.8 中存在的标签页式多文档 UI。

## 5. 法律与品牌边界

- 不反编译、不解包、不复制 Typora 私有源码。
- 不复制名称、图标、主题源文件、安装包素材和具有识别性的宣传文案。
- 可以根据公开资料独立重现用户可观察的界面、视觉效果、行为、标准 Markdown 格式和公开主题接口。
- 外部截图和视频只作为研究证据与人工对照，不进入可分发产品资源。
- 发布前进行依赖许可证审计、商标检索和产品界面法律复核。

## 6. 固定基线与变更控制

- 产品基线固定为 Typora 1.13.8 在 Windows 10/11 上公开可确认的可观察产品表现。
- 开发期间 Typora 新版本不自动进入范围；新增能力必须建立单独变更提案。
- 公开依据按 [`REF-*` 证据台账](22-typora-1.13.8-windows-evidence-baseline.md)记录来源、采集日期、版本适用性和可信度。
- 无法可靠确认的细节标记为 `evidence_gap`，不得凭推测实现后声称一致；已经确认的差异不能用缺口记录代替通过。
