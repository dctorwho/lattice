# 迭代路线图

估算按一名全职熟练开发者计算，不含等待人工验收、签名证书和商店审核。两人团队只能在编辑器内核稳定后有限并行，不能把同一文档模型拆给多人独立实现。

## 1. 里程碑总览

| 里程碑 | 目标                  | 预计     | 依赖          | 主要交付                                |
| ------ | --------------------- | -------- | ------------- | --------------------------------------- |
| M0     | 工程和规格基础        | 1–2 周   | 无            | 可构建安全 Electron 壳、CI、契约骨架    |
| M1     | 无损文件与源码编辑    | 4–6 周   | M0            | 可长期使用的源码编辑器、保存/冲突/恢复  |
| M2     | Typora 式混合编辑内核 | 8–12 周  | M1            | 基础 Markdown 单栏混合编辑、IME、撤销   |
| M3     | 工作区与桌面壳        | 5–7 周   | M2            | 文件树、文章列表、大纲、搜索、完整窗口  |
| M4     | 高级 Markdown         | 10–14 周 | M2、M3 命令层 | 表格、公式、图表、YAML、TOC、HTML、脚注 |
| M5     | 图片、剪贴板与主题    | 6–9 周   | M2、M3        | 资源事务、智能粘贴、主题和写作模式      |
| M6     | 导入、导出与打印      | 9–11 周  | M4、M5        | HTML、PDF、图片、Pandoc 导入导出适配    |
| M7     | 设置、兼容与质量收口  | 8–12 周  | M3–M6         | 偏好、快捷键、i18n、a11y、兼容矩阵通过  |
| M8     | Windows 发布          | 3–5 周   | M7            | 安装、关联、CLI、签名准备和 RC          |

总计约 54–78 个全职工程周；加入探索、返工和人工体验优化后，一人现实周期为 15–24 个月，兼职应按投入比例延长。

## 2. M0：工程基础

入口：规格获确认，工作目录可写，Node/pnpm/Git 可用。

交付：

- Git 仓库、electron-vite/React/TypeScript 工程和 lockfile。
- main/preload/renderer 分层，sandbox、CSP 和安全外链处理。
- `pnpm check`、Vitest、Playwright Electron、CI 和测试夹具目录。
- Zod IPC 基础、统一错误类型、Command Registry 空骨架。
- 架构决策记录和依赖许可证清单。

退出：安全壳端到端测试通过；渲染器不能访问 Node/裸 IPC；构建产物可启动。

## 3. M1：无损文件与源码编辑

交付：编码/EOL 模型、原子保存、外部冲突、恢复、CodeMirror 源码模式、新建/打开/保存/另存、查找替换和状态栏。

人工门禁：中文 IME 连续编辑 30 分钟；强杀恢复；外部编辑冲突；LF/CRLF/BOM 文件哈希验证。任何数据不变量失败都回到 M1，不允许进入混合模式。

## 4. M2：混合编辑内核

按风险顺序加入：标题/段落 → 强调/代码 → 引用/列表/任务 → 链接/图片 → 代码块。先解决显隐、selection、IME、undo，再增加输入规则。

退出：源码/混合切换不改变文本和历史；基础 Markdown 黄金语料通过；日用两周无光标跳跃、重复输入或源码漂移。

## 5. M3：工作区与桌面壳

交付：标题栏、菜单、固定工具栏、侧栏、文件树/列表、大纲、快速打开、全局搜索、文件操作和窗口恢复。

退出：10,000 文件工作区不阻塞输入；搜索可取消；文件删除/移动有确认与错误恢复；所有入口调用统一命令。

## 6. M4：高级 Markdown

每种复杂块独立通过“解析范围 → widget → 源码最小补丁 → 冲突拒绝 → 撤销”契约。顺序：YAML/TOC/Alerts → 代码块 → 表格 → 脚注/引用 → MathJax → Mermaid → HTML。

退出：复杂块失败时可靠回退源码；恶意输入安全测试通过；大文档降级策略生效。

## 7. M5：图片、剪贴板与主题

交付：拖放/粘贴图片、路径策略、复制/移动/删除事务、上传器接口、智能粘贴、复制格式、原创主题、自定义 CSS、焦点/打字机/拼写。

退出：所有文件副作用可解释并可恢复；主题不能覆盖安全 UI；复制到常见办公/浏览器场景人工通过。

## 8. M6：导入、导出与打印

顺序：共享只读渲染模型 → 带样式/纯 HTML → PDF/打印 → 图片 → 导出记忆 → Pandoc 进程适配 → Pandoc 导出 → Pandoc 导入。Pandoc 缺失是受支持状态，不是构建失败。

退出：导出不修改编辑会话；导入不修改源文件且失败不创建部分会话；离线运行；公式/图表/本地图片可嵌入或受控提取；错误包含可操作诊断。

## 9. M7：质量收口

交付：完整设置、快捷键覆盖、简中/英文、无障碍、性能、兼容矩阵、文档和用户迁移策略。每个 `COMP-*` 必须为 `passed` 或有明确 `documented_gap` 说明。

退出：四周内部日用无 P0/P1；所有发布门禁通过；没有假功能和未接线设置。

## 10. M8：Windows 发布

交付：NSIS、卸载、文件关联、命令行、单实例、窗口路由、签名准备、发布说明和回滚演练。自动更新在公开发布后作为独立受控任务启用。

退出：干净 Windows 10/11 VM 安装—编辑—导出—卸载全流程通过，RC 至少运行七天无阻断缺陷。

## 11. 变更规则

- 里程碑出口未通过时不得用“后续再修”解锁依赖任务。
- 新需求先加入需求和兼容矩阵，再进入任务；不得直接写代码。
- 影响文档模型、保存、IPC 或导出契约的变更需 ADR 和全量回归。
- Typora 新版功能只进入未来 backlog，不改变 1.13.8 验收基线。
