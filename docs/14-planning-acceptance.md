# 规划资料验收

本文件定义“可交给 Codex 开始一个迭代”的证据，不代表产品代码已经完成。

## 必需资料

- 产品章程、完整需求、复刻验收矩阵和 Typora 1.13.8 Windows 版本化公开证据台账。
- 进程/编辑器/文件/导出架构与公共接口。
- 技术栈、依赖准入和被排除方案。
- 数据无损、安全威胁和失败恢复。
- UI/交互、迭代路线、开发、测试、发布和风险文档。
- 根 `AGENTS.md`、Codex CLI runbook、`iterations/` 模板、M0–M8 状态和依赖图。
- 每个迭代的三份入口文档；状态需要时还包括测试报告和退出报告。

## 自动校验

在任何依赖安装或代码生成之前可运行：

```powershell
node scripts/verify-planning-docs.mjs
```

该命令验证：

- 必需文件存在、`iterations/state.json` 合法，M0–M8 唯一且状态有效。
- 迭代依赖存在、无自依赖和依赖环，状态转换符合依赖和人工门禁规则。
- 每个迭代拥有完整入口路径；状态需要的退出文件存在且归属于该迭代。
- 所有产品需求 ID 和 COMP-001..036 至少被一个迭代需求文档引用。
- 每个 `COMP-*` 至少关联一个有效 `REF-*`，每个 `REF-*` 的需求、迭代和 `TC-*`/`MAN-*` 映射均存在且所有权一致。
- 每个迭代至少有一个唯一、与迭代匹配的 `TC-*` 用例；每个 `manual_gate:true` 迭代至少有一个有效 `MAN-*` 用例。
- 用例文档包含自动用例、参数矩阵、证据与停止条件；启用人工门禁时还必须包含人工用例，且没有 `TBD` 或“待定”。
- 文档中的本地 Markdown 链接可解析，围栏成对。
- 活跃执行文档不含旧的细分执行状态或旧状态文件引用，且 `AGENTS.md` 小于 32 KiB。
- 最多一个迭代处于 `in_progress` 或 `awaiting_manual`。

## 人工校验

1. 随机抽取 M1、M2、M4、M6、M8，确认都有范围、依赖、验证和停止条件。
2. 确认无单一迭代要求在未经门禁时完成整个产品，无假 UI 作为完成方式。
3. 确认数据安全、IME、安全、导出和安装都存在强制门禁。
4. 确认没有复制 Typora 品牌、默认主题或私有源码的要求。
5. 使用 `docs/11-codex-cli-runbook.md` 的只读命令确认 Codex 能加载根 `AGENTS.md`。
6. 每个迭代随机抽取一个 `TC-*`，确认层级、参数、步骤、预期和自动化目标完整；对 `manual_gate:true` 的迭代抽取所有有效 `MAN-*`，确认人工步骤可复现。
7. 随机抽取 `REF-*`，确认 URL、采集日期、版本依据、Windows 适用性、观察、可信度和追踪映射均可核验。
8. 确认六套主题使用独立 CSS 和资源重现视觉效果，不复制 Typora 主题源文件。

## 开发启动条件

- 本校验通过。
- 用户接受完整复刻目标、Windows 10/11 范围、版本化证据基线和独立品牌边界。
- M0 保持 `passed`，M1 是唯一 `ready` 迭代，M2–M8 保持 `blocked`。
- Node 24.x、Git 2.50+ 和由 Corepack 固定的 pnpm 11.12.0 可用。
- 工作目录初始化 Git 后，Codex 按 runbook 选择并完成一个迭代；M1 开工前总计划重订必须通过本页自动和人工校验。
