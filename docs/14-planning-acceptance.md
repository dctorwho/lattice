# 规划资料验收

本文件定义“可交给 Codex CLI 开始开发”的证据，不代表产品代码已经完成。

## 必需资料

- 产品章程、完整需求和兼容矩阵。
- 进程/编辑器/文件/导出架构与公共接口。
- 技术栈、依赖准入和被排除方案。
- 数据无损、安全威胁和失败恢复。
- UI/交互、迭代、开发、测试、发布和风险文档。
- 根 `AGENTS.md`、Codex CLI runbook、任务模板、M0–M8 全任务和状态依赖图。
- `docs/test-cases/` 中 M0–M8 用例、参数矩阵、人工门禁、证据/停止条件和夹具目录。

## 自动校验

在任何依赖安装或代码生成之前可运行：

```powershell
node scripts/verify-planning-docs.mjs
```

该命令验证：

- 必需文件存在、`state.json` 合法、task ID 唯一且状态有效。
- 任务依赖存在、无自依赖和依赖环。
- state 中每个任务有规格，规格中的每个任务存在于 state。
- 所有产品需求 ID 和 COMP-001..036 至少被一个任务引用。
- 每个任务至少有一个唯一 `TC-*` 用例；每个人工门禁任务至少有一个 `MAN-*` 用例。
- 所有测试规格包含自动用例、参数矩阵、人工门禁以及证据与停止条件，且没有 `TBD`/“待定”。
- 文档中的本地 Markdown 链接可解析。
- 最多一个任务处于 `in_progress`。

## 人工校验

1. 随机抽取 M1、M2、M4、M6、M8 各一项，确认有依赖、需求、交付、验证和停止条件。
2. 确认无单条任务要求实现整个产品，无假 UI 作为完成方式。
3. 确认数据安全、IME、安全、导出和安装都存在强制门禁。
4. 确认没有复制 Typora 品牌、默认主题或私有源码的要求。
5. 使用 `docs/11-codex-cli-runbook.md` 的只读命令确认 Codex 能加载根 `AGENTS.md`。
6. 随机抽取每个迭代一个 `TC-*`，确认任务、层级、参数、步骤、预期和自动化目标完整；抽取全部 `MAN-*` 确认人工步骤可复现。

## 开发启动条件

- 本校验通过。
- 用户接受功能基线和独立品牌边界。
- `M0-T01` 为唯一首个 ready 任务。
- Node 24.x、Git 2.50+ 和由 Corepack 固定的 pnpm 11.12.0 可用。
- 工作目录初始化 Git 后，Codex CLI 按 runbook 执行；M0-T01 使用已记录的自举验证例外。
