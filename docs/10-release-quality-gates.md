# 发布与质量门禁

## 1. 发布等级

- **Developer build**：仅开发机，允许未完成任务，但不得违反数据和安全不变量。
- **Internal alpha**：M1/M2 通过，可日用基础编辑；M1/M2 范围内不存在已知复刻差异，但不宣称后续能力已经完成。
- **Feature beta**：M3–M6 通过，已进入范围的工作区、高级 Markdown、媒体、主题和导出复刻项全部通过。
- **Release candidate**：M7 通过，功能冻结，仅修阻断缺陷。
- **Stable**：M8 通过，签名、安装、回滚和文档完整。

## 2. 永久阻断条件

以下任何一项存在时不得升级发布等级：

- 静默数据丢失、损坏、范围外重写或外部修改被覆盖。
- 崩溃恢复错误宣称成功，或关闭流程绕过未保存确认。
- renderer 可获得 Node/裸 IPC，或不可信内容可执行系统命令。
- 中文 IME 重复/丢字、撤销跨越错误边界、模式切换改变源码。
- 安装/卸载删除用户文档、主题或工作区文件。
- P0/P1 未关闭，或关键测试被 skip/quarantine 无批准。
- 任一所属迭代仍有已确认的复刻差异，却被记录为 `passed`。

## 3. Alpha 门禁

- M0–M2 所有迭代 passed。
- DATA、EDIT、基础 MD 和 SEC 套件全绿。
- 连续两周内部日用，无数据不变量失败。
- 已知限制在欢迎页和发布说明中明确，不放置不可用按钮。

## 4. Beta 门禁

- M3–M6 通过，COMP-001..029 均有版本化公开依据、自动化证据和所需人工签署。
- HTML/PDF/图片导出在无网络、无 Pandoc 环境可用。
- 复杂 Markdown、图片事务、主题和剪贴板的自动化验收完成；仅当对应迭代经设计启用 `manual_gate:true` 时，再完成获批的人工门禁。
- 依赖漏洞无未评估高危；二进制来源和许可证清单完整。

## 5. RC 门禁

- 功能冻结，复刻验收矩阵全部 `passed`；不允许用 `evidence_gap` 替代已经确认的行为。
- 影响核心功能、数据安全、主要交互或主要视觉的 high/medium 证据缺口为零。
- Windows 10/11、100%–250% 缩放、简中/英文测试完成。
- 性能不低于预算，内存和长文档无持续增长。
- 用户文档、隐私说明、许可证、故障恢复和卸载行为完成。
- 从上一内部版本升级和设置迁移演练成功。

## 6. Stable 门禁

- RC 至少七天真实使用无 P0/P1。
- 干净 VM 执行下载/校验 → 安装 → 关联 → 打开 → 编辑 → 恢复 → 导出 → 卸载。
- 制品哈希、SBOM、许可证、签名状态和发布说明归档。
- 回滚到上一稳定版不会丢设置或文档；恢复格式向后兼容或有迁移工具。
- 支持渠道和安全报告入口可用。
- 已知产品差异为零，每个 `COMP-*` 均可追踪到 `REF-*`、迭代测试和出口证据。

## 7. 缺陷等级

- **P0**：数据损坏、权限逃逸、远程代码执行、安装删除用户数据。立即停线。
- **P1**：常用流程无法完成、IME/undo 严重错误、核心导出错误、频繁崩溃。阻断里程碑。
- **P2**：有合理绕过的功能、交互或 UI 缺陷。必须在所属迭代关闭，不能作为复刻完成后的已知差异发布。
- **P3**：轻微视觉、文案或低频增强。可进入 backlog。

## 8. 发布和回滚步骤

1. 从干净 tag 构建，不使用开发机未跟踪文件。
2. 运行完整门禁并生成测试、SBOM、许可证和哈希报告。
3. 签名后重新验证制品；签名步骤不得修改应用内容。
4. 小范围分发 RC，收集只含用户主动提交的诊断。
5. Stable 分批发布；发现 P0/P1 立即撤回制品并发布已签名回滚版本。

自用阶段可以不签名，但不能跳过数据、安全、安装和回滚验证。

## 9. M0 工程基础出口

M0 不是公开发布门禁，但必须为后续迭代建立可审计的候选链路：

1. 干净 Windows 检出使用 Node 24.18.0、pnpm 11.12.0 和冻结 lockfile，执行 `quality`、CodeQL 与 Dependency Review。
2. `pnpm check`、普通 E2E、安全、Windows x64 NSIS 打包和专用 packaged 测试全部通过。
3. `pnpm audit:m0` 生成生产依赖、MIT 许可证、零 high/critical 漏洞、零 moderate 及以上工具链漏洞、CycloneDX 1.6、工作流、品牌、包哈希和六步门禁证据；Dependency Review 另对 PR 新增的完整工具链执行精确宽松许可证集合门禁。
4. main 规则集要求 PR、`quality`、`codeql` 和 `dependency-review`，并以失败 PR/修复后 PR 证明门禁真正阻断而非仅存在配置文件。
5. MAN-M0-001 由普通 Windows 11 用户验证 unpacked/NSIS 启动、Lattice 品牌、未签名提示、DevTools/导航阻断、冻结 preload 表面和证据包，并显式签署通过或失败。

前四项完成后 M0 才能进入 `awaiting_manual`；第五项通过并形成 `05-exit-report.md` 后才可将 M0 设为 `passed` 并解锁 M1。M0 的未签名状态不得被解释为 M8 发布签名已完成。
