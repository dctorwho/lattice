# M1 全自动验收与门禁治理设计

## 背景

M1 当前已经完成文档生命周期、源码编辑、冲突、恢复、查找替换、状态栏和数据安全实现，并通过已有自动化套件，但状态停留在 `awaiting_manual`。阻断项 `MAN-M1-001` 要求评估人连续使用微软拼音 30 分钟、使用第三方输入法、手工编辑编码夹具、制造冲突、强制终止、检查恢复并签署证据。

该门禁来自早期风险规避策略，不是产品运行约束。固定 30 分钟没有与缺陷概率或覆盖率建立可验证关系，不能稳定重放，也不能进入 CI。字节保留、冲突状态、恢复修订、关闭决定和应用可观察到的 IME 事件都具有确定性边界，应由自动化直接验证。

## 决策

项目采用“自动化默认、有限时、可重放”的迭代出口策略：

- 取消 M1–M8 一律强制人工门禁的治理规则；`manual_gate` 字段保留为状态模型能力，但不再由迭代编号强制为 `true`。
- M1–M8 当前规划的 `manual_gate` 设置为 `false`。后续只有在出现无法通过受控 Windows 环境、虚拟设备或确定性测试适配器观察的物理边界时，才能通过独立设计变更重新启用；不能用主观手感或固定时长代替覆盖设计。
- M0 已完成的历史人工证据不重写，M0 状态和证据保持原样。
- M1 从 `awaiting_manual` 返回 `in_progress`，以新的自动验收用例补齐覆盖；全部出口证据通过后直接进入 `passed`，M2 随后进入 `ready`。
- 人工查看可以作为非阻断探索或缺陷复现手段，但不拥有迭代批准权，不进入完成条件。

`MAN-M1-001` 不静默删除。M1 测试文档保留一条“已废止人工用例”迁移记录，说明其每项能力由新的 `TC-M1-013` 和既有用例接管：

## 自动验收架构

### Windows Electron 边界

新增 `TC-M1-013`，在无 `ELECTRON_RENDERER_URL` 的真实生产 Electron 构建上运行。测试只使用 Playwright Electron 控制通道、主进程可控对话框替身、真实临时目录和 Chromium DevTools Protocol，不在产品 preload 增加测试后门。

测试按独立场景启动应用，每个场景具有固定 Playwright 超时和清理阶段。任何应用、子进程、文件事件或恢复等待超过预算都立即失败并终止对应进程；禁止无界循环和长期重试。

### IME 事件序列

应用并不直接调用微软拼音或第三方输入法，而是接收 Chromium 统一的 composition、beforeinput、input 和 selection 事件。自动测试通过 Chrome DevTools Protocol 的 `Input.imeSetComposition` 与 `Input.insertText` 向真实 CodeMirror 编辑面发送确定性序列，覆盖：

- 多阶段候选文本更新与最终提交；
- 中文、Emoji、组合字符和全角标点；
- 候选提交前后的跨行选区；
- 连续删除和长退格等价输入；
- 组合事务后的撤销与重做；
- 固定种子的大量短序列，验证无重复、丢字和错误历史分组。

输入法厂商候选窗口属于 Chromium 上游和操作系统 UI，不是本应用的可调用边界。M1 验证应用实际能影响的事件与状态，不再用输入法品牌或持续时长作为间接代理指标。

### 字节与文件生命周期

在 `tests/fixtures/bytes/` 提交版本化 Base64 夹具清单，包含空文件、UTF-8、UTF-8 BOM、UTF-16LE/BE BOM、LF、CRLF、混合换行、无末尾换行和非法 UTF-8。清单固定原始与预期 SHA-256、唯一允许编辑标记和关联需求。

Electron E2E 通过系统选择器替身把每个真实临时文件交给应用，使用编辑器把 `M1_EDIT_OLD` 精确替换为等长的 `M1_EDIT_NEW` 并保存。测试读取磁盘字节并与冻结预期字节和哈希比较；非法 UTF-8 必须保持只读且磁盘哈希不变。任何范围外变化都直接失败。

### 冲突、恢复与关闭

- 冲突场景分别从干净临时文件启动，自动覆盖比较、取消、重新加载、本地另存、二次确认覆盖；每个分支读取本地、外部和另存文件的 SHA-256，证明需要保留的版本仍可恢复。
- 恢复场景为应用分配隔离的临时 user-data 目录，输入未保存正文，等待有界的一秒恢复写入后强制终止 Electron 进程，再用同一目录重启并验证最新修订和正文哈希。测试结束清理临时目录。
- 关闭场景以独立应用实例验证保存、不保存和取消。保存分支核对磁盘字节，放弃分支核对窗口关闭且没有意外文件，取消分支核对窗口和未保存正文仍存在。

### 公开证据

`TC-M1-013` 输出不含正文与绝对用户路径的 JSON 证据摘要，记录 Windows、Node、pnpm、Electron、应用提交、夹具哈希、场景结果、`REF-001..005` 和对应 `COMP-*`。Playwright 截图只保存固定的非敏感测试正文状态。

M1 的公开证据都是文件生命周期、编码、恢复、源码模式和状态统计等可观察功能，不包含必须由人主观判断的像素级视觉目标。自动断言和固定截图足以形成当前迭代的直接证据。

## 验证顺序

1. 用规划单元测试证明旧模型会错误拒绝 `manual_gate:false`，再修改治理实现。
2. 为每个新增自动验收场景先编写失败测试或最小可运行特征测试，确认失败原因是能力或证据缺失。
3. 运行 M1 聚焦单元、集成和 Electron E2E，确认每个替代场景独立通过。
4. 运行规划、中文文档、格式、Lint 和类型检查。
5. 运行完整 `pnpm check`、`pnpm test:e2e`、`pnpm test:security`、`pnpm test:performance`。
6. 复核所有 M1 需求、测试用例、`REF-*`、`COMP-*` 和状态证据后生成出口报告。

所有命令必须设置明确超时并在完成、失败或超时后退出。不得通过 `.skip`、重试、降低断言、固定成功输出或人工签名替代自动证据。

## 风险与处置

- CDP composition 行为若与当前 Electron Chromium 接口不兼容，测试必须失败并记录接口差异；不能退化为仅调用 `insertText` 后声称覆盖 IME。
- Windows watcher 和恢复存在调度延迟，只允许等待明确状态或文件出现并设固定上限，不允许无限轮询。
- 强制终止后必须确认子进程退出；清理失败视为测试失败，不保留后台 Electron。
- 自动截图受字体和 GPU 差异影响时，M1 只断言结构、文本和状态，不引入未经定义的像素容差。
- 自动化发现任何字节漂移、静默覆盖或恢复错误时，立即保留失败夹具并停止 M1 出口。

## 回滚

若新的自动验收基础设施本身不稳定，M1 保持 `in_progress`，回滚尚未证明的测试适配器并修复根因。不得恢复 30 分钟人工门禁作为临时绕过，也不得把缺失覆盖记为通过。
