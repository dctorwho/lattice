## 最终交付物

- 无损 `SourceBuffer`、`DocumentSession`、搜索和状态领域模块。
- 经 Zod 验证的文件打开、保存、监视、恢复和窗口生命周期 IPC 契约。
- 原子保存、外部修改监视、恢复存储与协调服务。
- 基于 CodeMirror 6 的源码编辑器、查找替换、状态栏和文档命令流程。
- 九个冻结字节夹具、真实生产 Electron 自动验收及脱敏证据生成器。
- 自动化优先的迭代治理规则、中文测试报告与本出口报告。

## 重要实现与文档变更

- Markdown 源字符串仍是唯一权威；React 不镜像完整文档，编辑器历史与领域历史通过有界同步保持一致。
- 保存使用同目录临时文件、刷盘、原子替换和 Windows 有限退避；外部冲突不允许静默覆盖。
- renderer 继续运行在沙箱中且无 Node 集成，只通过窄且类型化的 preload API 访问特权操作；恢复写入不能自报磁盘路径取得授权。
- M1 的原人工验收被可重复、阻断性、有限时的 Windows 自动验收替代；只有无法自动控制的物理边界才允许未来迭代显式设置 `manual_gate:true`。

## 已知限制与剩余风险

- M1 仅交付源码编辑与文档核心；混合编辑、工作区、主题、扩展 Markdown、导出和安装发布由 M2–M8 依次实现。
- `REF-002..005` 部分资料早于目标版本；后续获得更高可信度的 1.13.8 专属证据时，应回归对应 COMP 项。
- Windows 输入法候选窗口属于操作系统和 Chromium 上游；产品门禁覆盖应用收到的组合事件、最终文本及撤销历史。

## 回滚方法

若后续发现 M1 数据完整性回归，立即停止迭代推进，将 M2 恢复为 `blocked`、M1 标记为 `failed`，保留问题文件的脱敏哈希与最小回归夹具，在 M1 分支修复根因并重新运行全部数据完整性、Electron、安全和性能门禁。不得以规范化源码或丢弃恢复数据作为回滚手段。
