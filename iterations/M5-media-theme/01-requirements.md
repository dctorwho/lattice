# M5 需求

## 迭代上下文

- 迭代：`M5`
- 状态权威：`iterations/state.json`
- 全局规则：[产品章程](../../docs/00-product-charter.md)、[架构](../../docs/03-architecture.md)、[数据安全与安全边界](../../docs/05-data-safety-and-security.md)和[测试策略](../../docs/09-test-strategy.md)

## 目标

交付安全、可逆的媒体工作流和写作展示工具：可互操作剪贴板、图片生命周期管理、受限上传、独立主题以及保持编辑器事务保证的写作辅助模式。

## 用户可观察结果

- 用户可以按可预测语义粘贴和复制纯文本、Markdown、净化后的 HTML 与图片，且每次操作只产生一个撤销单元。
- 用户可以插入、移动、重命名、重新加载和删除图片，Markdown 链接与磁盘操作始终可解释且可恢复。
- 用户可以选择原创浅色、深色或跟随系统主题，使用安全自定义 CSS 主题，并使用专注、打字机、只读、拼写、Emoji、智能标点以及行段移动功能。

## 范围

剪贴板转换与净化；图片插入来源、路径策略、资源事务和上传适配器；主题加载、CSS 作用域、系统模式变化、热重载和公开 Typora CSS 约定适配，但不捆绑 Typora 资源；专注、打字机、只读模式和指定写作辅助。

## 非目标

云剪贴板同步、无限制命令执行器、主题市场或复制 Typora 品牌与默认主题；改变 Markdown 源码权威、序列化富文本模型或让图片文件操作静默且不可逆。

## 前置条件与外部依赖

M4 必须已为 `passed`。依赖现有 CodeMirror 源码事务、类型化 IPC、授权对话框和沙箱渲染边界，以及 Windows 剪贴板 API、受控回收站集成和外部编辑器剪贴板夹具；自动化上传验证使用虚假可执行文件。

## 风险与缓解措施

剪贴板 HTML、主题、图片和上传器输出均视为不可信，渲染或补丁前必须净化与验证并拒绝远程或脚本逃逸。资源失败使用 `ResourceTransaction`、回滚和明确修复指引。主题 CSS 只作用于文档区域，系统对话框不受影响。IME 与大文档风险由事务分组以及端到端和性能用例约束。

## 迭代级验收标准

1. 每个映射需求和兼容项都有自动化证据，证明不存在未授权执行或永久丢失。
2. 资源操作要么提交相符的 Markdown 与磁盘状态，要么保留原件并报告可恢复失败。
3. 自定义 CSS 不得执行脚本、加载禁用资源或隐藏安全界面。
4. M5 通过前，所有必需人工观察均由指定评估人记录并批准。

## 入口完整性

本文档、详细设计和测试用例是三份入口文档。三者必须完整，且前置迭代均为 `passed`，M5 才能进入 `ready` 或 `in_progress`。本文档不包含子任务、任务级状态或任务级归属。
